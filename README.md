# 루센토 사용자 템플릿

현재 루센토 작업 폴더의 `sirsoft-basic` 1.2.7을 복사한 독립 사용자 템플릿입니다.
식별자는 `lusento-site`, 표시명은 `루센토`, IIFE 전역 이름은 `LusentoSite`입니다.
레이아웃·컴포넌트의 디자인과 동작을 유지하고 식별자·등록 이름·배포 메타데이터만 분리했습니다.
원저작자의 MIT 라이선스와 저작권은 `LICENSE`에 그대로 보존합니다.

## 파일 구성

- `template.json`: 이름, 버전, 의존성, 배포 자산.
- `layouts/`, `routes.json`, `extensions/`: 페이지, 부분 레이아웃, 라우트와 템플릿 확장.
- `src/components/`, `src/handlers/`: 컴포넌트와 템플릿 전용 핸들러.
- `src/styles/main.css`: 템플릿 공통 스타일.
- `components.json`, `editor-spec.json`, `editor-spec/`: 컴포넌트와 편집기 등록.
- `lang/`, `seo-config.json`: 번역과 SEO 설정.
- `dist/`: 설치에 사용하는 빌드 완료 JS/CSS. GitHub에도 포함해야 합니다.

## 기존 루센토 모듈 연결

`lusento-catalog`는 별도 모듈로 유지합니다. 상품 API, 상품·카테고리 화면,
판매처 기능, 사이드바 주입과 공통 상품 스타일을 이 저장소로 복사하지 않습니다.
상품 스타일은 기존 모듈의 `resources/css/product-list.css`에서 계속 수정합니다.
템플릿의 비교 페이지는 기존 `/api/modules/lusento-catalog/` API를 사용합니다.

모듈 연결에 쓰이는 `_user_base`, `main_content_area`, `main_content`, `content` 슬롯은
그대로 유지합니다. 모듈의 공개 사용자 라우트 연결은 템플릿 식별자가 아닌 `user` 타입을
기준으로 작동합니다. 기존 이름을 유지하는 공통 핸들러와 상태 키도 그대로 둡니다.

원본의 모듈·플러그인 의존성은 `template.json`에 보존했습니다.
루센토의 현재 상품 화면에는 `lusento-catalog >=0.36.1` 활성 상태가 필요합니다.
이 제약은 기존 운영 기준 버전을 사용하며 로컬 미배포 버전 0.37.0을 요구하지 않습니다.
카탈로그 모듈 자체의 코어 요구사항(`>=7.1.0`)도 운영에서 충족해야 합니다.
이 템플릿 분리 작업은 카탈로그의 미배포 기능이나 모듈 업데이트를 포함하지 않습니다.

## 로컬 빌드와 검증

그누보드7의 `templates/_bundled/lusento-site/`에 이 폴더를 배치합니다.
Node.js 22 환경에서 템플릿 폴더를 기준으로 실행합니다.

```sh
npm ci
G7_BUILD_SOURCEMAP=0 npm run build
npm run test:run
```

단독 Vite 빌드는 이 폴더의 `dist/`만 만듭니다. 코어를 부팅하거나 DB·확장 캐시를
갱신하지 않습니다. 레이아웃 테스트는 그누보드7 코어 테스트 도구를 사용하므로
위 배치 위치에서 실행해야 합니다. GitHub 저장소만 단독으로 받아도 빌드는 가능하지만,
코어를 사용하는 전체 테스트에는 그누보드7 체크아웃이 필요합니다.

## GitHub에 올릴 범위와 패치 흐름

GitHub 저장소의 루트에 **이 폴더의 내용만** 둡니다. 상위 루센토 프로젝트 전체를
올리지 않습니다. `template.json`이 저장소 루트에 있어야 수동 설치기가 찾습니다.
`node_modules`, 환경 파일, 키, DB 덤프, 개인 작업 산출물과 테스트 결과는 제외합니다.
자동 배포나 CI는 포함하지 않습니다.

`template.json`의 업데이트 출처는 비공개 저장소 `Froala-K/lusento-site`입니다.
원본 Basic 저장소의 업데이트를 직접 받지 않습니다.
원본 변경을 가져올 때는 별도로 검토하여 반영합니다.

패치는 다음 순서로 준비합니다.

1. 이 템플릿만 수정하고 관련 테스트를 실행합니다.
2. `template.json`, `package.json`, `package-lock.json`의 버전을 함께 올리고 변경 이력을 기록합니다.
3. 프로덕션 빌드 후 `dist/`까지 저장소에 포함합니다.
4. 동일 버전 태그와 GitHub Release를 발행합니다. 설치기는 릴리스의 소스 아카이브를 사용합니다.
5. 운영 반영은 별도 확인 후 템플릿 관리에서 수행합니다. DB 편집 레이아웃의 유지/덮어쓰기를 먼저 결정합니다.

현재 코어는 최신 **Release**를 기준으로 업데이트를 감지하고, 태그는 `v0.1.1`과
`0.1.1` 형식을 모두 지원합니다. 태그만 발행하면 최신 업데이트 감지 대상이 아닙니다.
비공개 저장소는 운영 서버의 `G7_UPDATE_GITHUB_TOKEN` 접근 권한이 별도로 필요합니다.
Codex/GitHub 계정 연결만으로 운영 서버에 토큰이 전달되지는 않습니다.
현재 설치기는 릴리스가 없을 때 `main`/`master` ZIP으로 폴백하면서 토큰을 전달하지
않으므로, 비공개 저장소는 Release 경로를 사용해야 합니다.

## 운영 반영 전에 확인할 것

이 복사본은 로컬 Basic 소스 기준입니다. 관리자에서 저장한 DB 레이아웃·번역·첨부는
소스 폴더 복사만으로 이관되지 않습니다. 운영 DB 편집본을 임의로 동기화하지 않았습니다.
활성화 전에 현재 Basic의 DB 편집본과 소스 차이를 확인하고 필요한 항목만 명시적으로
이관해야 합니다. 모듈이 주입한 상품 레이아웃·사이드바는 모듈 소유로 유지합니다.

`sirsoft-basic`과 `sirsoft-admin_basic`은 그대로 보존합니다.
GitHub에 버전을 올려도 운영 템플릿이 자동으로 설치·활성화·업데이트되지는 않습니다.
